# Reproduction notes

## Recommended reading order

1. Inspect `data-inventory.json` and run `python scripts/inspect_datasets.py`.
2. Review `scripts/multivariate_regression.py` for the classical calibration baseline.
3. Open the ANN and CNN notebooks in `notebooks/baselines/` to inspect loading, wavelength selection, normalization, target selection, and model definitions.
4. Review the TCT notebooks and the occlusion loop in `notebooks/explainability/`.
5. Inspect the transfer and wastewater experiments after checking their input tables and checkpoint assumptions.

Notebook filenames describe their research role. They are preserved experiment variants, not a single automated training pipeline. In particular, the file in `notebooks/experimental/` is an exploratory implementation using a configured `TimeSeriesTransformerForPrediction`; despite its original source filename, it does not download a verified pretrained model.

## Configurable paths

`research_paths.py` resolves all supplied inputs relative to the repository. Optional environment variables are:

| Variable | Default | Purpose |
| --- | --- | --- |
| `PLASMA_DATA_DIR` | `data/` | Root of the curated CSV hierarchy |
| `PLASMA_EXTERNAL_DATA_DIR` | `data/external/` | Additional acquisitions not supplied |
| `PLASMA_ARTIFACT_DIR` | `artifacts/` | Original checkpoints and histories |
| `PLASMA_OUTPUT_DIR` | `outputs/` | New per-experiment results |

The code creates a separate output directory for each notebook. This prevents different experiments, several of which originally saved to the same `Cu_Transfer.h5` filename, from overwriting one another or the supplied artifacts. Within a notebook, rerunning a save cell can replace its generated output; copy results to a new run directory or set `PLASMA_OUTPUT_DIR` before another run if those outputs must be retained.

The copper Grad-CAM/SHAP notebook loads the checkpoint generated by its own preceding training cells. The transfer notebooks load the supplied `artifacts/checkpoints/Cu_Transfer.h5` and the original corresponding NumPy history. Model architecture compatibility must be checked before transfer: the source snapshot does not prove which notebook run created each shared checkpoint.

## Supplied data and missing acquisitions

All numerical CSV, NPY, and H5 files in the primary source folder are included byte-for-byte under English paths. The checkpoints are approximately 3.0 MB, 5.7 MB, and 10.3 MB individually, so no large-file substitution was needed. Three supplemental datasets were recovered and copied byte-for-byte: recollected training, recollected testing, and the combined wastewater dataset.

Historical absolute paths to standard training/testing files now resolve to the corresponding long/short tables supplied with this snapshot. These are the available research snapshots; byte identity with files formerly stored on another workstation cannot be established. The separate online acquisition was deliberately not replaced by the standard testing table.

Additional acquisition slots remain:

- `data/external/test_long.csv`
- `data/external/test_short.csv`
- `data/external/online_testing_long_ontime.csv`

The notebook catalog lists their consumers. Missing-input checks are local to the cells that use them, so the earlier supplied-data sections remain inspectable. Do not substitute one testing dataset for another solely because its column names or filename are similar.

Standard raw tables have 1,912 columns, including metadata and wavelength columns. Most neural notebooks select exactly 1,862 spectral features from positions `18:1880`. Averaged tables contain 1,905 columns and have a different metadata offset. Preserve the original column order, duplicate placeholder column labels, row order, and per-notebook element masks. No numeric data cleaning was performed during packaging.

## Original experiment assumptions

- Normalization commonly clips intensities at 60,000 and scales by 60,000. Some variants also zero predefined wavelength regions for other elements. These choices were retained.
- Data splitting, seeds, losses, architectures, and training budgets remain as supplied. Several notebooks monitor a separately named testing dataset during training or use it for validation. Report those experiments as originally designed; their metrics should not be presented as fresh, untouched holdout performance.
- Some older variants use unconventional variable names for `train_test_split` results. Their assignments and subsequent use were preserved to avoid silently changing the experiment.
- The `tct_nickel` baseline contains a testing-preprocessing cell that clips `spectrum` rather than `spectrum_test`. This apparent source inconsistency was retained and should be reviewed before producing new results.
- Several original filenames and output names use `Cu` even in other target-element experiments. Public notebook names identify the intended experiment, but preserved model and history filenames should not be treated as proof of the target or architecture.
- The custom loss labeled SMAPE uses a different branch when the true concentration is zero. This is the implemented research loss, not an assertion of a universal metric definition.
- The regression relative-error plot contains fixed comparison values from the original script. It does not automatically consume newly generated regression results.
- Grad-CAM, SHAP, and the exploratory time-series Transformer depend on version-sensitive APIs. Their complete runtime has not been validated during packaging.

## Environment and validation scope

Imports require NumPy, pandas, SciPy, Matplotlib, scikit-learn, TensorFlow/Keras, and H5 support. SHAP is needed by the copper explanation notebook. PyTorch and Hugging Face Transformers are needed by the experimental prototype; some other notebooks optionally seed PyTorch when installed.

Old inline version comments included TensorFlow 1.12 and other annotations that conflict with APIs such as `tf.random.set_seed` and `MultiHeadAttention`. Those comments were removed from the curated copies. `requirements.txt` provides a proposed TensorFlow 2.15 compatibility environment rather than claiming the old annotations form a reproducible lockfile. No costly training or hardware operation was run during preparation.

The three supplied H5 files identify Keras **2.6.0** and the TensorFlow backend in their stored metadata. The checkpoint model names are `ANN_Model`, `CNN_Model`, and `Temporal_Convolutional_Transformer`. This confirms their saved model families, but it does not establish compatibility with every notebook variant or reproduce the original full environment.

The included validator checks Python syntax, notebook structure, cleared outputs, English-only text/path names, and the hashes of copied numerical data and artifacts. Dataset inspection verifies schema and row counts. These checks do not establish scientific reproducibility, classifier accuracy, checkpoint architecture compatibility, or the success of a full notebook run.
